## Escopo e Fonte de Verdade

Este arquivo e o contrato central do pacote `addon/globalPlugins/nvdastudio/`.

Regras centrais:
- O baseline oficial do projeto e `NVDA 2026.1.1+`.
- O projeto nao mantem compatibilidade ativa com versoes anteriores a esse baseline.
- Codigo legado, arquivos sem uso real, fluxos duplicados e documentacao depreciada devem ser removidos, nao preservados.
- `build.py` e o unico fluxo canonico de build e empacotamento atualmente suportado.
- **v2.1.0**: Wiring de novos módulos — evaluation_framework, code_sandbox, agent_memory,
  api_key_validator, model_registry, web_search_tool, context_compressor.
  **Correção 2026-08-30 (auditoria de mecanismos órfãos):** esta linha afirmava 9 módulos e
  duas das afirmações eram falsas. `prompt_optimizer` NUNCA foi ligado — tem zero referências
  em produção, e o próprio README o lista em "Próximas prioridades de wiring", contradizendo
  este contrato. `mcp_connector` foi REMOVIDO do projeto (Regra 3, resposta hardcoded sem
  chamada de rede real) e não existe mais. Contrato que declara feito o que não foi é pior que
  contrato omisso: quem lê para de procurar.

### Layout de Pacotes

Os modulos estao organizados fisicamente em subpacotes dentro de `addon/globalPlugins/nvdastudio/`:

| Subpacote | Conteudo |
|-----------|----------|
| `ai/` | clarifier, critic, llm_client, llm_factory, provider_client, ollama_client, model_registry |
| `builder/` | addon_builder, addon_loader, nvda_context, api_key_validator, code_sandbox, context_compressor, trajectory_compressor |
| `core/` | orchestrator, agentic_loop, planner, orch_types, checkpoint_manager |
| `gui/` | studio_dialog, settings_panel |
| `memory/` | session_memory, agent_memory, memory_manager, conversation_manager, session_recap |
| `skills/` | metadados SKILL.md das skills nativas (+ skill_registry.json na raiz do pacote) |
| `sub_agents/` | 14 agentes especializados |
| `tool_system/` | registry, executor, approval, builtins/ |
| `tools/` | skills_hub, tool_gateway |
| `utils/` | logger, project_policy, engineering_principles, evaluation_framework, iteration_budget, smart_retry, user_visible_text, task_tracker, timeouts |
| `lib/` | dependencias vendorizadas para CPython 3.13 (httpx, tinydb e cadeias transitivas) |

### Contrato do fluxo principal

1. Nenhum codigo gerado pela LLM e executado automaticamente.
2. O planner decide a decomposicao semantica; o sistema decide modelos e validacoes de forma deterministica.
3. `orchestrator.py` delega o loop autonomo a `AgenticLoop` que decide estrategias dinamicas por FSM:
   - `EXECUTE_NORMAL`: executa pipeline normalmente
   - `RETRY_SAME`: repete step com mesmo modelo + fix_instructions
   - `MENTAL_SIMULATION`: dry-run do plano ANTES de executar (detecta deadlocks)
   - `SWAP_MODEL`: troca modelo por step (kimi-k2.6 <-> deepseek-v4-flash)
   - `ENSEMBLE_VERIFY`: 2 modelos + arbitro deepseek-v4-flash para consenso em steps criticos
   - `SURGICAL_REPLAN`: replaneja apenas sub-arvore a partir do step que quebrou
   - `SELF_PLAY_ADVERSARIAL`: gera cenarios adversos para testar robustez
   - `CONSULT_MEMORY`: busca sessoes similares em session_memory para aprendizado
   - `TOOL_CREATION`: gera ferramentas Python temporarias sob demanda
   - `FULL_REPLAN`: replaneja todo o pipeline
   - `FORCED_NOVEL`: quebra ciclos de oscilacao A->B->A
   - `DECOMPOSE_GOAL`: decompoe query grande em sub-goals
   - `ASK_USER_HINT`: pausa e pergunta ao usuario (usa callback _on_clarify)
   - `DIAGNOSE_GIVE_UP`: para apenas quando streak de 3 sem progresso ou estrategias esgotadas
4. `planner.py` escolhe modelos por tipo de etapa e provedor via `model_registry.py`; `alto` e o padrao da UI e usa o par heavy/light auditado do provedor. Modelo concreto configurado pelo usuario ou override `NVDASTUDIO_<PROVIDER>_<TIER>_MODEL` substitui o tier automatico.
5. Pesquisa web real via `web_researcher.py` quando query contem sinais de necessidade (api, documentacao, versao, changelog, etc.)
6. `studio_dialog.py` possui UI unificada:
   - Painel esquerdo: criacao (descricao, nome, log de progresso, nova sessao) + secao conversar/iterar (carregar addon, historico de chat, campo de mensagem)
   - Painel direito: codigo gerado, salvar, empacotar, fechar
   - Sem wx.Notebook, sem troca de abas
7. `addon_loader.py` so le texto de pasta ou `.nvda-addon`; nunca importa nem executa o addon carregado.
