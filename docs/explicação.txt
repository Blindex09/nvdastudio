Imagina que você é uma pessoa cega, usuária do NVDA, e tem uma ideia na cabeça: "quero que meu leitor de tela me diga a hora toda vez que eu pressionar um atalho de teclado." Antes do NVDAStudio, para transformar essa ideia em realidade você precisaria escrever código Python, entender as entranhas do NVDA, formatar um pacote instalável, criar documentação, testar tudo — ou depender de um desenvolvedor.

O NVDAStudio elimina essa barreira completamente. Você descreve o que quer, em português, e um time de inteligências artificiais trabalha em conjunto para entregar um addon completo, funcional e acessível.

---

**Como começa a experiência**

O usuário abre o NVDAStudio com um atalho de teclado. Uma janela surge, e o NVDA anuncia o nome do programa. Tem um campo de texto no centro da tela onde a pessoa escreve o que quer criar — pode ser uma frase simples, como escreve uma mensagem para um amigo. Não tem formulário técnico, não tem campos difíceis. É só descrever.

Se o pedido for um pouco ambíguo ou incompleto, o sistema não trava nem devolve erro. Ele faz perguntas. Pergunta coisas simples: "Para qual programa você quer usar?", "Você quer configurar isso pelo painel do NVDA?" — no máximo cinco perguntas curtas, e apenas quando realmente precisa de mais informação para fazer algo de qualidade. O nível técnico do usuário é detectado automaticamente, então as perguntas se adaptam. Uma pessoa leiga recebe perguntas diferentes de um desenvolvedor.

Tem um guardião ali também. Se o pedido envolver algo potencialmente perigoso — como monitorar tudo que o usuário digita, ou acessar dados privados sem avisar — o sistema recusa explicando o motivo em linguagem simples. Não é um aviso frio de sistema. É uma explicação que a pessoa entende.

---

**O que acontece por dentro**

Depois que o pedido está claro, um pipeline começa a rodar. A pessoa vê as mensagens de progresso aparecerem na tela em tempo real: "Planejando...", "Gerando código...", "Verificando acessibilidade...", "Criando documentação...". Em torno de 45 segundos, tudo está pronto.

Por trás disso existe um time de doze agentes de inteligência artificial, cada um especialista em uma coisa diferente. Não é um único modelo fazendo tudo — é como uma agência, com funções bem definidas.

Um agente faz apenas o planejamento: ele recebe o pedido e decide quais serão os próximos passos, em que ordem, e qual especialista vai cuidar de cada um. Outro agente é responsável apenas por escrever o código Python do addon. Um terceiro só audita esse código para garantir que segue as regras do NVDA — são vinte e uma regras diferentes que precisam ser respeitadas para o addon funcionar corretamente com o leitor de tela. Existe um agente que valida se o código sequer executa sem erros de sintaxe. Outro cria o arquivo de instalação, outro gera a documentação, outro escreve os testes automáticos.

Tem ainda um agente que faz revisão de design antes de qualquer linha de código ser escrita. Ele age como um time com três perspectivas diferentes: um que questiona decisões de design, um que lembra das restrições técnicas do NVDA, e um que defende a experiência do usuário final. Só depois dessa triagem o código começa a ser produzido.

E existe um avaliador que examina o resultado de cada agente antes de passar para o próximo. Esse avaliador faz duas perguntas separadas: "entregou exatamente o que foi pedido?" e "segue todas as regras de qualidade e acessibilidade?" Se a resposta for não, ele não apenas rejeita — ele explica o que está errado e dá instruções específicas para o agente corrigir sozinho. O agente tenta de novo, com esse feedback, até três vezes. Se ainda assim não conseguir, o sistema escalona para um modelo de IA mais potente.

Tem um detalhe importante sobre como a memória funciona. Quando um agente comete um erro em um passo anterior, todos os agentes seguintes ficam sabendo desse erro. Isso evita que o mesmo problema apareça de outra forma mais adiante no processo.

---

**O que é entregue no final**

Ao terminar, o usuário tem na tela quatro entregas: o código completo do addon, o arquivo de configuração para instalação, um guia do usuário em HTML totalmente acessível para leitores de tela (com navegação por landmarks, hierarquia de títulos, listas semânticas para passos de instalação), e uma suíte de testes automáticos. Tudo isso junto, pronto para usar.

O usuário então escolhe o que quer fazer com esse material. Pode salvar os arquivos numa pasta, pode gerar um pacote instalável, pode instalar direto no NVDA sem sair do NVDAStudio — nesse caso o sistema faz tudo automaticamente e anuncia quando terminou. Existe até uma opção para preparar o addon para submissão à loja oficial do NVDA, com todas as informações de metadados que esse processo exige.

---

**O modo de iteração**

Depois de criar um addon, a pessoa pode continuar trabalhando nele. O NVDAStudio tem um modo de conversa onde o usuário carrega um addon existente e bate papo com o sistema sobre mudanças. "Quero adicionar uma configuração de volume", "Quero mudar o atalho de teclado", "Quero que ele funcione no Firefox também." O sistema responde como um assistente, e quando percebe que a mudança exige regenerar partes do addon, dispara o pipeline de forma cirúrgica — sem sacrificar o que já estava funcionando.

O histórico da conversa é salvo. Se o usuário abre o NVDAStudio dias depois, o contexto da última conversa ainda está lá.

---

**O que o usuário pode configurar**

As configurações são poucas e diretas. Tem a chave de API do Groq, que é o serviço de inteligência artificial usado — sem ela nada funciona, e o sistema valida a chave antes de aceitar. Tem a pasta onde os addons gerados serão salvos. Tem o idioma das mensagens do sistema, com suporte a português, inglês e espanhol. Não existe configuração de modelo, de agente, de temperatura de IA nem nada parecido — essas decisões são todas automáticas. O usuário não precisa saber que elas existem.

---

**Onde o projeto está hoje**

O NVDAStudio está na versão 37.0.0, com mais de mil e oitenta testes automáticos cobrindo cada parte do sistema — todos passando. A base oficial é o NVDA 2026.1.1, a versão mais recente. O pipeline de doze agentes está completo. A interface de acessibilidade está construída sobre as regras mais atuais do NVDA e do wxPython, que é o kit de interface gráfica que o NVDA suporta. A documentação gerada pelos addons segue as mais recentes diretrizes de acessibilidade web, incluindo suporte a navegação por landmarks — o tipo de navegação que usuários de leitores de tela usam no dia a dia.

O projeto todo foi construído do zero para ser usado por pessoas cegas, criando ferramentas para pessoas cegas. A interface não é uma adaptação de algo que foi pensado para visão — ela foi projetada desde o início para funcionar auditivamente, com anúncios relevantes, sem poluição sonora, sem confiar em cores, ícones ou posição visual de elementos na tela.

É um sistema que transforma intenção em software funcional, sem exigir que o usuário saiba programar.
